A Quick Overview

Static vs. Dynamic Web Pages

  • Static web page

    • The content is all there in the HTML sent by the server.
    • When you open the page, you already see everything in the source code.
    • Easy to scrape with functions like rvest::read_html().

  • Dynamic web page

    • The content is loaded or changed by JavaScript after the page loads.
    • When you first open the page, some content may not be in the HTML yet.
    • Harder to scrape — you may need tools that run JavaScript, like chromote, httr::live_session, or Playwright.

Key Points

  1. Static pages usually send the full HTML content in the initial server response. TRUE

    • Example: a simple blog page. You can see all the posts by viewing page source.

  2. Dynamic pages may require executing JavaScript to load the full content. TRUE

    • Example: a product page where prices or images load after the page finishes loading.

  3. Dynamic pages may require tools like httr::live_session, chromote, or Playwright to manipulate the page to capture all the desired content. TRUE

    • These tools simulate a real browser and run the JavaScript so you can get the full content.

  4. Static pages can only be scraped with APIs, not with HTML parsing. FALSE

    • Static pages can be scraped directly with HTML parsing (like rvest::read_html()).
    • APIs are optional; they’re just another way to get the data.

Simple analogy

  • Static page → a printed book: all the content is already there.
  • Dynamic page → a TV screen: some things appear after you press buttons or wait for animations.

What is HTML?

  • HTML = the language used to build webpages.
  • Think of it like the skeleton of a webpage: it says what each part is (heading, paragraph, image, link, etc.).
  • Browsers read HTML to know what to show on the page.

Tip for scraping

  • Look for tags that contain the data you want.
  • Often you combine the tag with a class or id using a CSS selector.

Example: div.product

Example: div.product \(\to\) grab all <div> elements with class="product"

  • Imagine a webpage has boxes for each product.
  • Each box is a <div> element.
  • The ones that are products have class=“product”.

So when we say:

div.product

It means:

“Find all <div> boxes that have the class called product.”

It will grab all product sections and ignore other <div>s, like ads or headers.

Why it’s useful

  • Each product’s name, price, and details are inside that <div class="product">.
  • By grabbing the div.product first, you can then look inside it for the specific info you want.

CSS selector you most likely need

  • You would use:
"div.product"

as the CSS selector in your html_element() (or html_elements()) function to grab the product sections.

1. html_element()

  • Returns the first match.
  • If nothing matches the selector, it returns NA (or an empty value in R).
  • This is useful if you expect there might be missing elements — it won’t break your code, you just get NA.

2. html_elements()

  • Returns all matches as a list of elements.

  • If no elements match, it returns an empty list (length 0).

  • It does not automatically give NA for missing items inside the matches.

  • So, if some elements exist but some expected sub-elements inside them are missing, you have to check inside each element and handle missing values yourself.

  • html_element() on a missing element → returns NA.

  • html_elements() on a selector with no matches at all → returns empty list.

*Summary for scraping**

Function Returns if element exists Returns if element missing
html_element() The first match NA
html_elements() All matches Empty list list()

Note:

HTML uses “tags” (in pairs) to define the scope of an element

  • HTML uses tags like <p> and </p> to show where something starts and ends.

  • Everything between the pair of tags belongs to that element.

Example: <p>This is a paragraph.</p> → “This is a paragraph” is inside the <p> element.

Note:

Can HTML tags be nested within other tags?

NO.

  • HTML tags define the structure of the content (<p>, <div>, <h1>, etc.).

  • CSS properties define the style of elements (color, font-size, border, etc.).

  • You cannot put HTML tags inside CSS properties. They are completely separate.

*Correct relationship:**

  • HTML tags create elements \(\to\) CSS styles those elements using selectors, classes, or IDs.

So:

HTML tags cannot be nested inside CSS properties.

Note:

Multiple elements on a web page can share the same class or id

  • Class: many elements can have the same class.

    • Example: many <p class="highlight"> on a page → all highlighted.

  • ID: usually only one element should have a specific id, but sometimes people reuse them.

Here’s the answer clearly:

  • Multiple elements can share the same class \(\to\) TRUE
  • Multiple elements should NOT share the same id \(\to\) FALSE (IDs are supposed to be unique per page)

So the statement:

“Multiple elements on a web page can share the same class and id”

is FALSE because id should be unique, even though class can be shared.

Class → many elements can have it

ID → only one element should have it

Note:

CSS “selectors” can identify one or more specific elements on a page.

  • A CSS selector is like a pointer that tells the browser or scraper which element(s) you want on the page.
  • It can point to just one element or many elements.

Examples:

  1. Select one element

    • #main-title \(\to\) picks the element with the id “main-title”

  2. Select multiple elements

    • .product \(\to\) picks all elements that have class “product”
    • p \(\to\) picks all paragraphs on the page

So CSS selectors are flexible: they can select one or many elements, depending on what you want.

Note:

  • A CSS class is like a name you give to some HTML elements.
  • You can then tell all elements with that class how they should look.

Example in words:

  • You have several paragraphs that should all be red and bold.
  • You give them the class highlight.
  • Then in CSS, you say: “Make everything with class highlight red and bold.”
  • Result: all those paragraphs get the same formatting automatically.

Key point:

Classes let you style multiple elements at once without touching each one individually.

Note:

Can CSS selectors be combined?

  • A CSS selector tells the browser which element(s) to target.
  • You can combine selectors to be more specific and pick exactly what you want.

Example in words:

  • Suppose a webpage has:

    <div class="product">
  <p class="price">$10</p>
</div>
<div class="product">
  <p class="price">$15</p>
</div>

  • Selector: div.product p.price

    • This means: pick the <p> elements with class “price” that are inside a <div> with class “product”.
    • You are combining div.product and p.price to be very specific.

*Key point:**

By combining selectors, you can target exactly the elements you want, even if there are many similar elements on the page.

###In short

  • HTML tags = structure
  • CSS classes = style
  • CSS selectors = a way to pick elements
  • Tags can be inside each other \(\to\) nested
  • Selectors can be combined to get specific elements
  • Many elements can share the same class (and sometimes id)

HTML vs XML

  • HTML = makes a webpage look nice. It tells the browser: “Show a heading, show a paragraph, make it bold.”
  • XML = stores data in a structured way. It tells programs: “Here is a name, here is an age, here is a price.”

Extra tips:

  • HTML tags are pre-made like <p> or <h1>.
  • XML tags are made by you like <name> or <price>.
  • HTML is for browsers; XML is for data.

HTML vs CSS

  • HTML = the skeleton of a webpage

    • Think: “This is a heading, this is a paragraph, this is a button.”

  • CSS = the style/appearance of the page

    • Think: “Make this heading blue, this paragraph bigger, this button round.”

Why it matters for scraping?

  • You scrape HTML (the content).
  • But CSS selectors (from CSS) help you find exactly what to scrape.

HTML defines the structure of the elements on a web page and CSS describes the formatting of the elements.

What is the DOM (Document Object Model)?

  • The DOM is like a map or tree of a webpage.
  • It represents the structure of the page in a way programs (like browsers or scrapers) can understand.
  • Every element in the page—headings, paragraphs, images, links—is a node in this tree.

Is DOM part of HTML, XML, or CSS?

  • Not exactly part of them, but it represents the structure of HTML or XML in memory.
  • HTML → the DOM shows all HTML elements as nodes.
  • XML → the DOM shows XML elements as nodes.
  • CSS → can style elements in the DOM, but CSS itself is not part of the DOM.

Simple way to remember:

  • HTML/XML = the content and structure of the page.
  • DOM = the tree map of that content in the browser or program.
  • CSS = the style/appearance applied to elements in the DOM.

Analogy

  • HTML/XML = the blueprint of a house
  • DOM = the 3D model of the house you can walk through
  • CSS = the paint, decorations, furniture

HTML = the content and structure of the page.

DOM = a tree map of HTML elements that programs and browsers can use.

CSS = the appearance or style applied to the DOM elements.

Important

  1. Each webpage has different content and structure.

    • One page may have <div class="product">, another may have <article> or no products at all.

  2. DOM is built from the HTML of that specific page.

    • Every page has its own DOM tree, depending on its HTML.

  3. CSS affects styling, but doesn’t make the DOM the same.

“Every web page uses the DOM concept, meaning browsers represent its HTML as a tree of nodes, but each page has a different DOM depending on its HTML.”

What are CSS selectors?

  • Think of a webpage as a big tree of boxes. Each box is an HTML element, like a paragraph, heading, image, or button.
  • A CSS selector is like a map or address that tells your scraper exactly which box(es) you want to look at.

In short: CSS selectors help you point to the right parts of a webpage.

Common CSS selectors you can use in scraping

  1. Tag selector

    • Picks elements by their HTML tag name.
    • Example: p → selects all paragraphs
    • Simple: h1, div, span, a (links)

  2. ID selector

    • Selects a specific element with a unique id.
    • Syntax: #idname
    • Example: #main-title → picks the element with id="main-title"

  3. Class selector

    • Selects elements with a certain class name.
    • Syntax: .classname
    • Example: .product-price → all elements with class="product-price"

  4. Attribute selector

    • Selects elements with a specific attribute.
    • Syntax: [attribute=value]
    • Example: [href="/contact"] → selects a link that goes to /contact

  5. Descendant selector (space)

    • Selects elements inside another element.
    • Syntax: parent child
    • Example: div p → all paragraphs inside any <div>

  6. Child selector (>)

    • Picks elements that are direct children of a parent.
    • Syntax: parent > child
    • Example: ul > li → list items that are directly inside a <ul>, not deeper

  7. Multiple selectors (,)

    • Select multiple things at once.
    • Example: h1, h2, h3 → selects all headings

  8. Pseudo-classes

    • Special selectors for positions or states, like :first-child or :last-child.
    • Example: ul li:first-child → first item in each list

Notes

Package

  • html_nodes(), html_elements(),html_text()andhtml_text2()`

  • The functions are from the same R package: rvest.

  • They are used in web scraping to grab content from a webpage.

Functions

  1. html_nodes() \(\to\) updated to html_elements()

    • What it does: find elements on the page using a CSS selector.
    • Example: grab all paragraphs (p) or all elements with class .price.
    • Old:
page %>% html_nodes("p")
  • New:
page %>% html_elements("p")

  1. html_text() → still works, but html_text2() is newer

    • What it does: get the text inside the elements you found.

    • html_text2() is better at handling extra spaces, line breaks, and messy HTML.

    • Old:

page %>% html_nodes("p") %>% html_text()
  • New:
page %>% html_elements("p") %>% html_text2()

Summary:

  • html_nodes() \(\to\) html_elements()
  • html_text() \(\to\) html_text2() (optional but recommended)
  • Both are from rvest.
